# 操作简化计划（面向高级管理员）

目标：把「高级管理员每天真正会做的事」压到最低点击次数。管理员不是录入员，也不是最终用户；
他们一天里 90% 的操作是**给一群人打今天的考勤**、偶尔**处理请假/补录**、月底**导出**。
其余设置、同步、更新、外观都属于一年改一次的东西，不该占用一级入口。

## 一、现在的问题（真机压测记录）

| 场景 | 现在需要几步 | 具体摩擦 |
| --- | --- | --- |
| 给一个人登记 | 5 步 | 首页 CTA → sheet 选人 → 编辑器 → 签到时间（滚轮）→ 签退时间（滚轮）→ 保存 |
| 给 5 个人登记同一种状态 | 5 + 4×N 步 | 批量登记藏在快捷卡里，进去还要再选人、再设时间 |
| 改一个时间 | 2 步 + 拖动 | 时间只能用滚轮，实测从 09:00 拖到 18:00 要试 3–4 次 |
| 找一个人改状态 | 3 步 | 人员列表行内没有动作，要点 `...` 再进 sheet |
| 筛一批记录 | 4 层 | 筛选 sheet → 状态 sheet / 人员 sheet / 日期 sheet |
| 销假 | 3 步 + 日历两次 | 要改开始日期和结束日期，再保存 |

一级界面负担：底部 4 个 tab、首页 1 张 KPI 大卡 + 3 个快捷卡 + 2 个区块 + 6 个管理入口。
对「只想登记」的管理员来说，一天里 80% 的像素是无用的。

## 二、简化原则

1. **默认值优先**：一句话能表达的操作不要问第二个问题（时间默认现在、请假默认今天 1 天事假、状态默认正常）。
2. **行内操作**：能在一行上完成的事，不要进二级页。
3. **入口收敛**：一级入口 ≤ 3 个；同步/外观/更新等降级为二级页或状态条。
4. **不改数据模型**：这一轮只改交互与信息架构，避免与并发开发（同步、请假、更新）冲突。
5. **可回退**：每期独立开关，旧路径保留一个大版本，出问题能切回。

## 三、分期计划

### P0 —— 一屏完成「今天的登记」（1.5 人日）

| # | 改动 | 现在 → 目标 |
| --- | --- | --- |
| 1 | 首页改成「今日名单」列表：每人一行，右侧 4 个状态快捷键（正常/迟到/缺勤/请假） | 5 步 → **1 步/人** |
| 2 | 行内点击即保存，时间默认取当前时间；长按或点名字才进编辑器 | 去掉选人 sheet |
| 3 | 列表顶部「批量」模式：勾选多人 → 底部浮条「设为正常 / 迟到 / 缺勤」 | 批量登记从快捷卡搬到主位 |
| 4 | KPI 从 hero 大卡压成一行文字：`已登记 12/16 · 请假 1 · 待登记 3` | 首屏省出 ~320pt |
| 5 | 时间面板加预设（08:30 / 09:00 / 12:00 / 18:00 / 现在）+ 键盘输入 | 滚轮从必选变兜底 |

验收：单人登记 ≤ 1 次点击；5 人同状态 ≤ 6 次点击；首屏不滚动能看到今日名单前 6 人。
度量脚本：`adb shell input tap` 计数 + `screencap` 时间戳，回归时跑同一脚本对比。

### P1 —— 入口与二级页收敛（2 人日）

| --- | --- | --- |

## 四、明确不做

- 不加多级审批流、不加排班/打卡机对接、不加聊天与消息中心；
- 不动数据模型、不动同步协议（本轮只改交互层）；
- 不为了简化删功能：被收起的入口在二级页都能找到，不做**纯删减**。

## 五、风险与回退

| 风险 | 处理 |
| --- | --- |
| 行内点击即保存 → 误触 | 保存后该行 2 秒内可「撤销」，并在底部提示 |
| 收起入口后找不到 | 设置与记录页提供搜索/「全部功能」入口 |
| 与并发开发冲突 | P0 只动 `today_page.dart` 与新增 `today_roster.dart`，不碰请假/同步文件 |
| 老用户肌肉记忆 | 保留旧「今日登记」面板一个版本，设置里给「经典登记模式」开关 |

## 六、执行顺序

1. 先做 P0-1/2/3（名单 + 批量 + 默认时间），这一步吃掉 80% 痛点；
2. 再做 P0-4/5（KPI 压扁、时间预设）；
3. 每完成一项跑一遍 `flutter test` + ADB 点击计数脚本，截图存档到 `evidence/`；
4. P1 逐条上线，导航改造放最后一项单独提交，便于回滚；
5. P2 作为收尾，跟大字号回归一起做。

## 七、更彻底的一步到位模型（建议纳入 P0，替换 1/2/3）

P0 只是把「5 步」压成「1 步/人」。如果目标是**高级管理员**，还可以再往下压：
让应用替他做判断，他只处理例外。

### 核心：三键 + 名单

首页就是今天的名单（常驻，不折叠），顶部一排三个键：

| 操作 | 行为 | 点击 |
| --- | --- | --- |
| **全员正常** | 把所有未登记的人按默认班次（09:00–18:00）一次落库 | 1 次 |
| **结束今天** | 未登记的人按缺勤落库，并提示待上传 | 1 次 |
| **请假** | 进请假面板（默认今天 / 1 天 / 事假 / 已确认） | 1 次 + 选人 |

日常 16 人：**1 次点击**完成 15 人的打卡，剩下 1 个迟到的人点他名字改状态。
体感上从「每人 5 步 ≈ 80 步」变成「2–3 步」，不是百分比优化，是数量级变化。

### 名单本身

- 每人一行：`姓名 · 工号` ＋ 右侧状态胶囊（未登记 / 正常 09:02 / 迟到 09:24 / 请假 / 缺勤）。
- **点行 = 登记现在**：按设备时间写入签到；已登记的人再点一次 = 写入签退。
- **左滑 = 缺勤，右滑 = 请假**（滑出确认条，2 秒内可撤销）。
- 长按 = 打开完整编辑器（补录、改历史时间、写备注）。编辑器从「默认路径」降级为「例外路径」。
- 已请假的人置灰并标「请假中」，点不开。

### 状态不再让人选

- 迟到 / 早退由时间与班次推导（班次与宽限分钟数放设置，默认 09:00 / 18:00 / 10 分钟）。
- 只有「请假」「缺勤」需要人工指定，且都能在名单上一步完成。
- 状态胶囊点一下可覆盖推导结果（弹出五选一），但这种覆盖应当少见。

### 为什么可行

- 管理员登记的是"我看到的这一刻"：默认当前时间比让他滚轮选 18:00 更准。
- 「全员正常」覆盖的是最常见的批量事实；例外永远是少数，逐条处理反而更快。
- 三个键都不需要进二级页，单手可点。

### 与前面分期怎么合

- 本节替换 P0 的 1/2/3；P0 的 4（KPI 压扁）与 5（时间预设）保留，作为名单顶部的补充信息与例外路径。
- 新增工作量约 +0.5 人日（推导规则 + 撤销 + 滑动动作），总计 P0 ≈ 2 人日。
- 风险：一键全员正常可能误用 → 需要「撤销本批」按钮（保留最近一次批量操作快照 5 秒），以及二次确认文案写清人数。
## 八、落地进度（本轮已完成）

已按第七节实现，`flutter analyze` 干净，`flutter test` 23 项全过，真机逐步验收。

| 项 | 实现 | 文件 |
| --- | --- | --- |
| 今日名单 | 首页即名单，未登记在前、已登记在后、请假置灰排最后 | `features/home/presentation/today_page.dart` |
| 一点登记 | 点行记签到（当前时间），再点记签退；已有签退则进编辑器 | 同上 + `Workspace.tapCheckIn/tapCheckOut` |
| 状态推导 | 迟到/早退由班次+宽限推导，不再让人选 | `core/data/shift.dart` |
| 三键 | 全员正常（统一记班次上班时间）/ 结束今天（余下记缺勤）/ 请假 | `today_page.dart` |
| 撤销 | 批量与滑动操作保留快照，顶部条「撤销」恢复 | `Workspace.restoreEntries` |
| 滑动手势 | 右滑=请假、左滑=缺勤（破坏性动作在尾随侧） | `today_page.dart` |
| 长按 | 打开完整编辑器（补录、精确时间、备注） | 复用 `entry_editor.dart` |

| 时间预设 | 08:30 / 09:00 / 12:00 / 18:00 + 滚轮兜底 | `core/widgets/sheet.dart: showTimePickSheet` |

顺带修掉的两个真机问题：

1. 底栏 PageView 原本支持左右滑动切 tab，与名单行的左右滑动手势打架（实测左滑被当成切到「设置」）。已改为 `NeverScrollableScrollPhysics`，tab 只从底栏切换。
2. 启动时的自动更新检查失败会弹 toast「检查更新失败」，盖住名单。后台检查改为静默，结果只写进设置项，需要时在更新页查看。
